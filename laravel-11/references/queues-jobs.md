# Laravel 11 Queues and Jobs

Source: https://laravel.com/framework/docs/11.x/queues.

## Laravel 11 defaults you should know

- New apps default to the `sync` driver (jobs run inline) — switch `QUEUE_CONNECTION` in `.env` to
  `database`/`redis` to actually queue.
- The `database` driver's `jobs` table ships in the default
  `0001_01_01_000002_create_jobs_table.php` migration. If it's missing:
  `php artisan make:queue-table && php artisan migrate`.
- Job classes generated by `make:job` use the single `Queueable` trait (11 change — Laravel 10
  stubs had four traits: `Dispatchable`, `InteractsWithQueue`, `Queueable`, `SerializesModels`).

## Creating a job

```shell
php artisan make:job ProcessPodcast
```

```php
<?php

namespace App\Jobs;

use App\Models\Podcast;
use App\Services\AudioProcessor;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Foundation\Queue\Queueable;

class ProcessPodcast implements ShouldQueue
{
    use Queueable;

    public function __construct(
        public Podcast $podcast,    // property promotion is the 11 stub style
    ) {}

    /**
     * Execute the job.
     */
    public function handle(AudioProcessor $processor): void
    {
        // Process uploaded podcast...
    }
}
```

`handle()` dependencies are injected by the container. Eloquent models passed to the constructor
are serialized by identifier and re-fetched on execution (with their loaded relations). To skip
relation serialization use `$podcast->withoutRelations()` or:

```php
use Illuminate\Queue\Attributes\WithoutRelations;

public function __construct(
    #[WithoutRelations]
    public Podcast $podcast,
) {}
```

## Dispatching

```php
use App\Jobs\ProcessPodcast;

ProcessPodcast::dispatch($podcast);                     // onto the queue
ProcessPodcast::dispatchSync($podcast);                 // run now, inline
ProcessPodcast::dispatch($podcast)->delay(now()->addMinutes(10));
ProcessPodcast::dispatch($podcast)->onQueue('emails');
ProcessPodcast::dispatchIf($accountActive, $podcast);
ProcessPodcast::dispatchAfterResponse($podcast);        // after response sent (FastCGI)
ProcessPodcast::dispatch($podcast)->afterCommit();      // wait for open DB transaction
```

The `afterCommit` chain method matters when dispatching inside a DB transaction — otherwise a
worker may pick up the job before the creating transaction commits and find missing rows.

## Attempts, timeouts, backoff

```php
class ProcessPodcast implements ShouldQueue
{
    use Queueable;

    public int $tries = 3;              // attempts
    public int $backoff = 60;           // seconds before retry (or: backoff(): array)
    public int $timeout = 120;          // seconds before the worker kills it

    public function retryUntil(): DateTime
    {
        return now()->addMinutes(30);   // time-based alternative to $tries
    }
}
```

Failure handling: add `failed(Throwable $e): void` to the job for cleanup/alerting; failures land
in the `failed_jobs` table and are visible via `php artisan queue:failed`.

## Job middleware

Put cross-cutting behavior in middleware returned from `middleware()`, not inside `handle()`:

```php
use Illuminate\Queue\Middleware\RateLimited;
use Illuminate\Queue\Middleware\WithoutOverlapping;
use Illuminate\Queue\Middleware\Skip;
use Illuminate\Queue\Middleware\ThrottlesExceptions;

public function middleware(): array
{
    return [
        new RateLimited('backups'),                          // uses RateLimiter::for('backups', ...)
        (new WithoutOverlapping($this->order->id))
            ->releaseAfter(60),                              // don't run two of the same order at once
        new ThrottlesExceptions(10, 5 * 60),                 // third-party API resilience
        Skip::when($this->shouldSkip()),                     // delete without running
    ];
}
```

Rate-limiter definitions live in `AppServiceProvider::boot()`:

```php
RateLimiter::for('backups', function (object $job) {
    return $job->user->vipCustomer()
        ? Limit::none()
        : Limit::perHour(1)->by($job->user->id);
});
```

## Unique and encrypted jobs

```php
use Illuminate\Contracts\Queue\ShouldBeUnique;
use Illuminate\Contracts\Queue\ShouldBeEncrypted;

class UpdateSearchIndex implements ShouldQueue, ShouldBeUnique
{
    // Locks via cache; uniqueId() / uniqueFor / uniqueVia() customize.
}
```

`ShouldBeUnique` prevents duplicate queued copies; `ShouldBeEncrypted` encrypts the payload
(sensitive data in the job body). Uniqueness needs a lock-capable cache driver (redis, database,
file, memcached, dynamodb, array).

## Running workers

```shell
php artisan queue:work                       # long-running process — don't restart per request
php artisan queue:work --queue=high,default  # priority order
php artisan queue:work --timeout=60
php artisan queue:restart                    # gracefully restart workers after deploy
php artisan queue:failed                     # list failures
php artisan queue:retry {uuid}               # retry one
php artisan queue:retry all
php artisan queue:flush                      # delete all failed jobs
```

In production run workers under Supervisor (or Horizon for Redis). Restart workers on every
deploy so code changes take effect — `queue:restart` is the graceful path; it requires a shared
cache.

## Job chaining and batching

```php
use Illuminate\Support\Facades\Bus;

Bus::chain([
    new ProcessPodcast($podcast),
    new OptimizePodcast($podcast),
    new ReleasePodcast($podcast),
])->dispatch();

$batch = Bus::batch([
    new ProcessPodcast($podcast1),
    new ProcessPodcast($podcast2),
])->then(fn (Batch $batch) => /* all succeeded */)
  ->catch(fn (Batch $batch, Throwable $e) => /* one failed */)
  ->finally(fn (Batch $batch) => /* always */)
  ->dispatch();
```

Batches need the `job_batches` table (included in the default jobs migration).

## Testing queued jobs

```php
use Illuminate\Support\Facades\Queue;
use App\Jobs\ProcessPodcast;

// The queue is faked; assert pushes...
Queue::fake();

ProcessPodcast::dispatch($podcast);

Queue::assertPushed(ProcessPodcast::class);
Queue::assertPushedOn('emails', ProcessPodcast::class);
Queue::assertPushed(fn (ProcessPodcast $job) => $job->podcast->id === $podcast->id);
Queue::assertNotPushed(AnotherJob::class);
```

Laravel 11 adds interaction assertions without writing custom fakes:

```php
$job = (new ProcessPodcast($podcast))->withFakeQueueInteractions();

$job->handle();

$job->assertReleased(delay: 30);
$job->assertDeleted();
$job->assertFailed();
```

See `testing.md` for the surrounding test harness.
